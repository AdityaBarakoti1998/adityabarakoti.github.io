A race condition, resolved in real time

Two requests hit the same appointment slot at the same instant. This is a simplified, honest replay of the concurrency test that actually ships with SmartQueue.

Two threads, one slot, zero double-bookings.

Both requests call ensureSlotExists() — an atomic INSERT ... ON DUPLICATE KEY UPDATE — then race for a PESSIMISTIC_WRITE lock on the same row. Whoever gets there first books and commits; the other waits, reads booked = true, and returns 409 instead of double-booking. This exact behavior is asserted in an integration test using ExecutorService and a dual CountDownLatch to force a genuine simultaneous race.
